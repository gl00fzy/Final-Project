02 • Problem Statement & Motivation

ที่มาและความสำคัญของปัญหา

ข้อจำกัดและปัญหาที่พบบ่อยในการตรวจข้อสอบแบบปรนัยในระดับมหาวิทยาลัย

เครื่อง OMR ราคาสูง & บำรุงรักษายาก

เครื่องอ่าน Optical Mark Reader แบบฮาร์ดแวร์เดิมมีราคาสูงถึง 100,000 - 300,000+ บาท

  • ต้องสั่งพิมพ์กระดาษคำตอบเฉพาะที่มีความหนาพิเศษและใช้หมึกดรอปเอาต์
  • หัวอ่านเซนเซอร์สกปรกง่าย เสียค่าบำรุงรักษาต่อปีสูง
  • มักรวมศูนย์อยู่ที่ส่วนกลาง อาจารย์แต่ละท่านเข้าถึงได้ยาก

การตรวจมือช้า & เสี่ยง Human Error

อาจารย์ส่วนใหญ่ตรวจข้อสอบด้วยมือ (ทาบแผ่นเจาะรู) ซึ่งมีข้อจำกัดร้ายแรง

  • ใช้เวลาเฉลี่ย 1-2 นาที/แผ่น นิสิต 200 คนต้องใช้เวลากว่า 4-6 ชั่วโมง
  • เกิดความเมื่อยล้า สายตาพร่ามัว ทำให้รวมคะแนนผิดพลาด
  • เมื่อนิสิตขอตรวจทาน ต้องเสียเวลาค้นหากระดาษคำตอบทีละแผ่น

ความยุ่งยากในการวิเคราะห์ข้อสอบ

การวิเคราะห์คุณภาพข้อสอบ (Item Analysis) มักไม่เกิดขึ้นจริงในทางปฏิบัติ

  • การคำนวณค่า $p$ (ความยาก), $r$ (อำนาจจำแนก), KR-20 ต้องคีย์ข้อมูลเข้าระบบสถิติเอง
  • ขาดการวิเคราะห์ตัวลวง (Distractor Analysis) เพื่อนำไปปรับปรุงข้อสอบ
  • เสียโอกาสในการพัฒนาคลังข้อสอบมาตรฐานของมหาวิทยาลัย

04 • Architecture & Tech Stack

สถาปัตยกรรมระบบ (System Architecture)

โครงสร้าง 3-Tier สถาปัตยกรรมแบบกระจายภาระประมวลผล (Edge Computing with WASM)

Client Tier Browser / Edge

Client-Side OMR Engine

ประมวลผลวิดีโอสตรีมสดบนเครื่องผู้ใช้ ลดภาระเซิร์ฟเวอร์เป็นศูนย์ (Zero Server Processing)

  • WebRTC Video API: ดึงภาพสดจากกล้อง 60 FPS ความละเอียด 720p/1080p
  • OpenCV.js (WASM): อัลกอริทึม Computer Vision Compiled เป็น WebAssembly ประมวลผลรวดเร็วระดับเนทีฟ
  • Tailwind CSS 3.4: Responsive HUD Interface สไตล์ ZipGrade
  • Chart.js 4.x: แผนภูมิฮิสโตแกรมและสถิติแบบอินเตอร์แอคทีฟ
Application Tier Backend API

PHP 8.2 MVC & RESTful API

จัดการตรรกะการตรวจข้อสอบขั้นสูง การยืนยันสิทธิ์ และการสร้างไฟล์เอกสาร

  • Grading Engine: ตรวจคำตอบแบบ Multi-Set, OR/AND Logic, Penalty Score
  • Auto-Regrade Engine: ปรับปรุงคะแนนใหม่อัตโนมัติเมื่อแก้เฉลย
  • tFPDF Unicode Engine: สร้างกระดาษคำตอบ A4 PDF พร้อมภาษาไทยสมบูรณ์
  • Google OAuth 2.0: ระบบยืนยันตัวตนผ่าน Google Workspace มมส.
Data Tier Storage & Security

MySQL 8.0 & File Storage

จัดเก็บข้อมูลคะแนนและภาพถ่ายกระดาษคำตอบอย่างปลอดภัยและมีประสิทธิภาพ

  • Normalized Schema: ตาราง exams, exam_shares, students, student_scores
  • Raw Answers JSON: จัดเก็บข้อมูลการฝนดิบ เพื่อใช้ในการ Regrade และ Item Analysis
  • Evidence Archiving: บันทึกภาพถ่ายกระดาษคำตอบที่สแกนเป็นหลักฐานอ้างอิง
  • Audit Logging: บันทึกประวัติการกระทำเพื่อความโปร่งใส ป้องกันการทุจริต

06 • Computer Vision Deep-Dive

อัลกอริทึมการประมวลผลภาพ (OMR Pipeline)

4 ขั้นตอนการแปลงภาพถ่ายจากกล้องเป็นข้อมูลดิจิทัลด้วย OpenCV.js

01

Fiducial Markers Detection

ตรวจจับจุดมาร์คเกอร์สี่เหลี่ยมสีดำ 4 มุมของกระดาษ

  • ค้นหา Contour ด้วย cv.findContours
  • ตรวจจับ 4 เหลี่ยมด้วย approxPolyDP (Aspect Ratio 0.4 - 2.5)
  • คำนวณจุดกึ่งกลางมวล (Moments) 4 มุม (TL, TR, BL, BR)
02

Perspective Transform

ดัดและปรับภาพที่เอียงให้เป็นระนาบสี่เหลี่ยมสมบูรณ์

  • คำนวณเมทริกซ์ 3x3 ด้วย cv.getPerspectiveTransform
  • ดัดภาพระนาบตรงด้วย cv.warpPerspective คืนขนาด A4
  • ชดเชยความเอียงจากการถือกล้องสมาร์ตโฟน
03

Adaptive Thresholding

แปลงภาพเป็นไบนารีขาว-ดำและกำจัดเงาตกกระทบ

  • แปลงภาพเป็น Grayscale ด้วย cv.cvtColor
  • ตัดเงาด้วย cv.adaptiveThreshold (Gaussian / Mean)
  • คำนวณเกณฑ์แยกบล็อกย่อย ชดเชยสภาพแสงไม่สม่ำเสมอ
04

Grid Mapping & Fill Density

ตรวจจับตำแหน่งวงกลมและคำนวณความหนาแน่นการฝน

  • แมปตำแหน่งวงกลมคำตอบและรหัสนิสิตตามพิกัดสัมพัทธ์ (Relative Grid)
  • คำนวณอัตราส่วนพิกเซลสีดำ Fill Fraction > 35%
  • ระบุตัวเลข 11 หลัก และคำตอบ ก-จ ได้อย่างแม่นยำแม้ฝนด้วยดินสอ 2B จาง
07 • Grading Algorithms & Innovation

ตรรกะการให้คะแนนขั้นสูง & ระบบ Auto-Regrade

รองรับกติกาการสอบทุกรูปแบบ พร้อมนวัตกรรมตรวจคะแนนใหม่ทันทีโดยไม่ต้องสแกนซ้ำ

Logic Rules ตรรกะการตรวจคำตอบขั้นสูง

ตอบสนองการสอบวัดผลหลากหลายสาขาวิชา

• Multi-Set Parallel (ชุด A, B, C, D)
ระบบตรวจจับวงกลมระบุชุดข้อสอบบนกระดาษ แล้วนำไปจับคู่เฉลยของชุดนั้นๆ โดยอัตโนมัติ
• ตรรกะ OR Logic (ตอบถูกตัวเลือกใดตัวเลือกหนึ่ง)
กรณีข้อสอบมีคำตอบถูกมากกว่า 1 ข้อ เช่น ตอบ ก หรือ ค ก็ได้คะแนนเต็ม
• ตรรกะ AND Logic (ต้องตอบครบทุกตัวเลือก)
สำหรับข้อสอบที่ต้องเลือกหลายคำตอบพร้อมกัน จึงจะได้คะแนนในข้อนั้น
• Penalty Score & Free Point (หักคะแนน / ยกประโยชน์)
รองรับการกำหนดน้ำหนักคะแนนรายข้อ, หักคะแนนกรณีตอบผิดเพื่อป้องกันการเดา, และการให้ฟรี
Killer Feature Speed: < 0.05s

09 • Statistical Engine & Analytics

การวิเคราะห์ผลคะแนนและคุณภาพข้อสอบ (Item Analysis)

คำนวณค่าสถิติเชิงลึกอัตโนมัติ ช่วยพัฒนาคุณภาพข้อสอบให้ได้มาตรฐานวิชาการ

Dimension 1 Descriptive Stats

สถิติภาพรวม & แผนภูมิการกระจาย (Histogram)

คำนวณคะแนนเฉลี่ย (X̄ - Mean), ส่วนเบี่ยงเบนมาตรฐาน (S.D.), คะแนนสูงสุด/ต่ำสุด และพลอตกราฟแท่งการกระจายตัวของคะแนน (Score Histogram) อัตโนมัติ

Dimension 2 p = R / N

ค่าความยากง่าย (p - Difficulty Index)

สัดส่วนผู้ตอบถูกรายข้อ เกณฑ์มาตรฐาน 0.20 - 0.80 พร้อมป้ายเตือนอัตโนมัติ: ง่ายเกินไป (p > 0.80) หรือ ยากเกินไป (p < 0.20)

Dimension 3 r = (R_H - R_L) / n

ค่าอำนาจจำแนก (r - Discrimination Index)

วัดความสามารถของข้อสอบในการแยกแยะนิสิตกลุ่มเก่ง (Upper 27%) และกลุ่มอ่อน (Lower 27%) ข้อสอบที่มีคุณภาพดีต้องมีค่า r ≥ 0.20

Dimension 4 KR-20 & Distractors

ความเชื่อมั่น KR-20 & การวิเคราะห์ตัวลวง

วิเคราะห์สัดส่วนการเลือกตัวเลือก ก-จ ของทั้งกลุ่มสูงและกลุ่มต่ำ เพื่อตรวจหาตัวลวงที่ไม่ทำงาน (ไม่มีคนเลือก) หรือตัวลวงที่มีข้อบกพร่อง

ความปลอดภัยและการบริหารจัดการผู้ใช้งาน

Roadmap

การพัฒนาต่อยอดในอนาคต

  • เชื่อมต่อระบบทะเบียนมหาวิทยาลัย (MSU Registrar API):
    ส่งผลคะแนนเข้าสู่ระบบเกรดของมหาวิทยาลัยได้โดยตรงไม่ต้องดาวน์โหลดไฟล์ CSV
  • รองรับข้อสอบอัตนัยด้วย Handwritten AI OCR:
    นำโมเดล AI มาช่วยตรวจลายมือเขียนคำตอบตัวเลขหรือคำสั้นๆ
  • ระบบสแกนไฟล์ภาพแบบเป็นชุด (Batch Upload PDF):
    รองรับการอัปโหลดไฟล์ PDF จากเครื่องสแกนความเร็วสูงในกรณีมีกระดาษหลายพันแผ่น

Q & A

ขอขอบพระคุณคณะกรรมการทุกท่าน

ยินดีรับฟังข้อเสนอแนะและตอบข้อซักถามเชิงลึกเกี่ยวกับระบบ MSU Scoring

github.com/gl00fzy/Final-Project

❓ ถ้านิสิตฝนจาง หรือกระดาษยับ ระบบจะตรวจจับได้ไหม?

▼
ระบบใช้ cv.adaptiveThreshold ชดเชยเงาและแสงสะท้อน และตั้งค่า Fill Fraction ไว้ที่ 35% หากนิสิตฝนจางมากจริงๆ อาจารย์สามารถกดปุ่ม "กรอกด้วยตนเอง (Manual Entry)" บนหน้าจอเพื่อบันทึกคะแนนได้ทันทีโดยไม่ต้องทิ้งกระดาษ

❓ ทำไมถึงเลือกประมวลผลบนเบราว์เซอร์ด้วย OpenCV.js?

▼
การรันบน WebAssembly (WASM) ในเครื่องผู้ใช้งานทำให้ได้ความเร็ว 30-60 FPS แบบเรียลไทม์ และลดภาระประมวลผลบนเซิร์ฟเวอร์เป็นศูนย์ (Zero Server CPU load) แม้อาจารย์จะตรวจข้อสอบพร้อมกัน 50 ท่าน เซิร์ฟเวอร์ก็ไม่ล่ม

❓ ความปลอดภัยของข้อมูลและภาพถ่ายกระดาษคำตอบ?

▼
ระบบบังคับใช้ HTTPS เพื่อความปลอดภัยของกล้อง, ควบคุมสิทธิ์ด้วย RBAC, แยกโฟลเดอร์จัดเก็บภาพตาม Hash ของ Exam ID, ป้องกัน Directory Listing, และมี Audit Logs บันทึกทุกกิจกรรม

❓ ถ้านิสิตลืมฝนชุดข้อสอบ (Set) ระบบจัดการอย่างไร?

▼
ระบบจะใช้ค่า Default Set จากตัวเลือกบนแถบ HUD ของอาจารย์ (เช่น ชุด A) และอาจารย์สามารถคลิกที่ประวัติคะแนนเพื่อสลับชุดและให้ระบบ Auto-Regrade คำนวณใหม่ได้ทันที
