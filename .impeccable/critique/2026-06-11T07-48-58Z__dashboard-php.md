## Anti-Patterns Verdict

**LLM assessment**: The dashboard reads as competent and functional, not obviously AI-generated. The restraint in color usage (yellow accent only) and consistent component vocabulary avoid the most common AI tells. However, the identical card grid pattern (same-sized cards with the same button layout repeated) is a mild tell — especially with 6 action buttons per card stacked in three grid rows. The layout is safe rather than designed.

**Deterministic scan** (7 findings):
- **gray-on-color** ×4: `text-gray-900` on `bg-yellow-500` across primary buttons (lines 57, 93, 125, 306). Not a true contrast failure (gray-900 on yellow-500 passes AA), but the detector flags it as a pattern worth reviewing.
- **overused-font** ×1: Inter detected as the sole font (line 15). This is a known false positive for product register — DESIGN.md's Inter-Only Rule explicitly chooses Inter for this tool.
- **single-font** ×1: Related to above. False positive; single font is a deliberate product decision.
- **border-accent-on-rounded** ×1: `border-b-2` on the loading spinner element (line 65). This is the standard Tailwind spinner pattern, not a decorative border stripe. False positive.

**Summary**: 4 real findings (gray-on-color), 3 false positives (font choices are deliberate per DESIGN.md, spinner border is functional).

## Overall Impression

A solid, functional dashboard that handles its core job — listing exams and providing access to scan/results/key/share/print/delete actions. The yellow-on-gray palette is clean and professional. The biggest opportunity: **the exam cards are overloaded with 6 action buttons each, creating decision fatigue.** A teacher with 20 exams faces 120 buttons on screen. The secondary opportunity: **error handling is primitive** (`alert()` popups everywhere), undermining the professional feel.

## What's Working

1. **Clear primary action**: The "สร้างชุดข้อสอบ" button is immediately visible, correctly uses the yellow accent, and includes an icon. No ambiguity about the page's primary affordance.
2. **Consistent card design**: Every exam card follows the same structure (title → metadata → actions), making the grid scannable. The responsive grid (`grid-cols-1 md:grid-cols-2 lg:grid-cols-3`) adapts well.
3. **Well-designed empty state**: The empty state (lines 289–295) uses a large icon, clear headline, and instructional sub-text. Better than "ไม่มีข้อมูล" alone.

## Priority Issues

### [P1] Button overload on exam cards
**What**: Each exam card has 6 action buttons in 3 rows (สแกน, สถิติ, จัดการเฉลย, โหลด CSV, พิมพ์, แชร์ข้อสอบ) plus a destructive "ลบข้อสอบ" ghost link — 7 interactive elements total per card.
**Why it matters**: Teachers scanning a list of exams face cognitive overload. With 10 exams, that's 70 buttons on screen. The working-memory rule (≤4 visible options per decision point) is violated per card. Primary actions (สแกน, สถิติ) compete equally with secondary actions (โหลด CSV, พิมพ์).
**Fix**: Surface only the 2 primary actions (สแกน + สถิติ) as visible buttons. Group secondary actions (จัดการเฉลย, โหลด CSV, พิมพ์, แชร์, ลบ) into a "⋯" overflow menu or a card-level dropdown.
**Suggested command**: `/impeccable distill dashboard.php`

### [P1] `alert()` error handling
**What**: All error feedback uses JavaScript `alert()` — lines 209, 211, 272, 277, 278.
**Why it matters**: `alert()` is blocking, modal, and styled by the browser — it breaks the professional feel of the UI and provides no recovery path. On mobile, it's especially disruptive. A university grading tool should never show raw browser dialogs.
**Fix**: Replace all `alert()` calls with inline toast notifications or the existing inline-message pattern used in `admin_dashboard.php` (`showMsg()` helper). Show success/error messages inside the relevant modal or as a page-level toast.
**Suggested command**: `/impeccable harden dashboard.php`

### [P2] No search, filter, or sort for exams
**What**: The exam list has no search bar, filter, or sort controls. Every exam is loaded and displayed in a flat grid.
**Why it matters**: A teacher with 15+ exams per semester (common at MSU) cannot find a specific exam quickly. The list will grow indefinitely. This is the "Power User" persona's primary frustration.
**Fix**: Add a search input above the grid that filters by exam title or code. Add sort controls (by date created, by title). Consider pagination or virtual scrolling for >20 exams.
**Suggested command**: `/impeccable craft search-filter for dashboard.php`

### [P2] Modals lack keyboard accessibility
**What**: All 4 modals (create, share, delete, print) are toggled via `classList.add('hidden')` / `classList.add('flex')`. No Escape key dismissal, no focus trapping, no ARIA roles.
**Why it matters**: Keyboard-only users (persona "Sam") are trapped inside modals. Screen readers don't announce modal state changes. This fails WCAG 2.1 AA for dialog accessibility.
**Fix**: Use the native `<dialog>` element or add `role="dialog"`, `aria-modal="true"`, focus trapping, and Escape key listeners to all modals.
**Suggested command**: `/impeccable audit dashboard.php`

### [P3] No help or onboarding
**What**: Zero contextual help, tooltips, or documentation links anywhere on the page.
**Why it matters**: A new teacher opening this system for the first time sees "จัดการข้อสอบ" with a create button and nothing else. The workflow (create exam → set answer key → scan → view results) is not explained. The "Confused First-Timer" persona (Jordan) has no guidance.
**Fix**: Add a brief onboarding callout for first-time users (dismissible banner explaining the workflow), and add tooltips to non-obvious actions like "โหลด CSV" and "สแกน".
**Suggested command**: `/impeccable onboard dashboard.php`

## Persona Red Flags

**Alex (Power User)**: No keyboard shortcuts detected. Cannot bulk-delete or bulk-share exams. No search or filter for exams — must visually scan the entire grid. With 15+ exams, this is unusable for a power user. The 7 buttons per card mean Alex must remember which row has "scan" vs "stats" every time, despite the consistent layout.

**Jordan (First-Timer / New Teacher)**: No onboarding. "OMR System" in the nav communicates nothing about what the tool does. The empty state says "กดปุ่มสร้างชุดข้อสอบใหม่เพื่อเริ่มต้น" but doesn't explain the overall workflow. After creating an exam, there's no guided next step (set answer key → scan). Jordan will create an exam, then be confused about what to do next.

**Sam (Accessibility-Dependent)**: Modals have no `role="dialog"`, no `aria-modal`, no focus trapping, and no Escape key support. The loading spinner has no `aria-label` or live region announcement. Tab order through 7 buttons per exam card is tedious. Delete confirmation relies on color (red) to signal danger — no icon in the modal header to reinforce the destructive nature for color-blind users (though the ⚠ SVG icon is present, which helps).

## Minor Observations

- **Print modal** opens in a new tab via `window.open()` — no loading feedback on the current page. User might click multiple times.
- **Share modal** has inline success/error messages (well done) but the success auto-closes after 1.8s — might be too fast for users who read slowly.
- **Exam card title** concatenates title + code without visual separation beyond parentheses. With long titles, the code gets lost.
- **"Powered by Advanced Agentic AI"** text appears on login/register but not on the dashboard — inconsistent footer treatment.
- **No favicon metadata beyond PNG** — missing Apple touch icon, manifest.json for PWA.
- **Tailwind CDN** (`cdn.tailwindcss.com`) is used in production — this should be a build step for performance.

## Questions to Consider

- Does the dashboard need to show ALL exams, or should past-semester exams be archived automatically?
- What would the dashboard look like if the primary action was "scan" rather than "create"? Most days, teachers come here to scan, not to create.
